## AC-1: Check catalogue listing
```gherkin
Given the tool with no AtlantisPB checkout available
When `node bin/validate-normative.js --list-checks` runs
Then every check in HANDOFF §6 (V-XML-001..012, V-APP-001..011, V-MOD-001..003, V-MAN-001..006, V-COH-001..006, V-PCAP-000) is printed with family, severity and source clause
And clauses derived from repo docs carry "(to confirm)", team conventions carry "team convention, not normative"
And exit code is 0
```

## AC-2: Every check has a source
```gherkin
Given the catalogue
When it is loaded
Then every entry has non-empty `id`, `family`, `severity` ∈ {blocking, should-fix, note}, and `source`
And the loader throws at startup if any entry violates this (fail loud, exit 2)
```

## AC-3: Skip, never pass
```gherkin
Given a run over any root (including an empty dir or a dir without tools/atlantis/layout.json)
When checks have no implementation yet, or a required source is absent (layout.json, schemas dir, xmllint)
Then each such check emits a `skipped` result with a human-readable reason
And skipped results are always printed (text and --json), with a summary count
And skipped results never change the exit code (0 when no blocking findings)
And the pcap family reports exactly: "skipped: no massa de teste exists in the repository; owner undefined (decisions.md)"
```

## AC-4: Resolution of root and schemas
```gherkin
Given `--root <dir>` or cwd when omitted
When the context is built
Then layout is read from `<root>/tools/atlantis/layout.json` (missing → recorded as unavailable source, not an error)
And schemas dir resolves `--schemas` → `$ATLANTIS_SCHEMAS` → `<root>/reference/schemas/` → unavailable-with-reason
And xmllint availability is probed once (`xmllint --version`) and recorded
And a non-existent `--root` or unreadable explicit `--schemas` exits 2 with a message
```

## AC-5: CLI contract and exit codes
```gherkin
Given args per HANDOFF §4 (`[target …]`, `--family` repeatable, `--schemas`, `--severity`, `--json`, `--list-checks`, plus `--root`, `--help`)
When run
Then `--family` filters checks (unknown family → exit 2)
And `--severity s` hides findings below s (skips still shown)
And `--json` prints `{ tool, version, root, sources, results: [...], summary }` where results are §5 findings or `{check, status:"skipped", reason, source}`
And exit 0 = no blocking finding, 1 = ≥1 blocking finding, 2 = could not run (bad arg/root)
And targets are accepted and passed through to the runner (resolution against the catalogue is phase 2+; unknown target format → exit 2)
```
