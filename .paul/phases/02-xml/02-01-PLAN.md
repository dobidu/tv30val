<acceptance_criteria>

## AC-1: AtlantisPB adapter
```gherkin
Given --root with tools/atlantis/{catalog,layout}.js and lib/ids.js
When the xml family runs
Then it loads them via require(<root>/tools/atlantis/…) once and uses them for ID lookup, kebab IDs and expected paths
And when any is missing or throws on load, every check needing it is skipped with the reason (including the error message)
And XML files are discovered by scanning `xmls/<type>/*.xml` for the five XML_TYPES (directory via layout pattern, not hard-coded, when layout.js exposes it; fallback documented)
```

## AC-2: V-XML-001 well-formed
```gherkin
Given an XML file
When xmllint is available
Then `xmllint --noout` decides; errors → blocking finding with xmllint's message and line
When xmllint is absent
Then the built-in reader decides (unbalanced/mismatched tags, bad attribute syntax, multiple roots, missing root) and the finding evidence says "checked by built-in reader (partial)"
And a file that fails 001 is not passed to 002–006 (those report skipped "not well-formed")
```

## AC-3: V-XML-002/004/005 schema-bound
```gherkin
Given schemas dir available AND xmllint available AND the XSD for the type found (filename map in namespaces.js, "(to confirm)")
When validating
Then `xmllint --noout --schema <xsd>` runs; each error becomes a finding: enumeration/pattern/facet errors → V-XML-004, "not expected"/"missing child" ordering errors → V-XML-005, anything else → V-XML-002
And when any precondition is missing, 002, 004 and 005 are each skipped per file with the specific missing piece (no schemas dir / xmllint absent / XSD <name> not in <dir>)
```

## AC-4: V-XML-003 namespace
```gherkin
Given a well-formed XML of type T
When T has an expected namespace recorded in lib/normative/namespaces.js
Then root element's namespace URI must equal it, and the root local name must equal T; mismatch → blocking finding with expected vs actual
And types without a recorded namespace (BAMT, ESG, AEAT today) → skipped "expected namespace for T not recorded"
```

## AC-5: V-XML-006 file name ↔ ID ↔ catalogue
```gherkin
Given xmls/<type>/<name>.xml
Then the ID derived from the file name (ids.fromFolderName) must exist in the catalogue (catalog.findArtifact) with matching type
And the ID in the first line of the header comment, when present, must equal it
And layout.xmlPath(ID) must equal the actual relative path
And any mismatch → blocking finding naming which of the three disagrees
```

## AC-6: V-XML-011 ESG triple
```gherkin
Given ESG artifacts in the catalogue or files under xmls/esg/
When an ESG number NNN appears in any of SERVICE/SCHEDULE/CONTENT
Then all three files must exist; missing ones → blocking finding
And when no ESG artifact exists in catalogue or tree → skipped "no ESG artifacts"
```

## AC-7: Targets and pending checks
```gherkin
Given targets (IDs or paths)
Then only matching XML files are checked; non-XML IDs are ignored by this family
And V-XML-007..010, 012 report skipped "not implemented yet (v0.1 plan 02-02)"
```
