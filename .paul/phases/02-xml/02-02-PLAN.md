## AC-1: V-XML-007 header fields (team convention, should-fix)
```gherkin
Given an XML file that passed V-XML-001
When its first comment is parsed
Then it must contain: ID + type on line 1, a source-document version (`v\d+(\.\d+)?`), a `Used by:` section, `Specification variant:`, and an `Assumptions` section
And each missing field → one should-fix finding naming the field
And a file with no comment at all → one finding "no header comment"
```

## AC-2: V-XML-008 header cases ↔ catalogue
```gherkin
Given the header's `Used by:` lines and the catalogue artifact's `cases`
Then cases listed in the header but not in the catalogue, and catalogue cases missing from the header, are each reported (should-fix), with both lists in evidence
And no `Used by:` section → skipped "header lists no cases (see V-XML-007)"
And adapter unavailable or artifact not in catalogue → skipped with reason
```

## AC-3: V-XML-009 BALD validity windows
```gherkin
Given a BALD element with validFrom / validUntil
When no window attribute exists → pass (valid from reception, indefinitely)
When validUntil is a fixed date in the past (relative to run time)
Then blocking finding — unless the header's `Validity windows:` paragraph declares the window is deliberately past/expired, in which case pass with evidence "declared deliberate in header"
And an unparseable date → blocking finding
And non-BALD files are not checked by 009
```

## AC-4: V-XML-010 signalled URLs resolve
```gherkin
Given BALD bcastEntryPackageUrl "<stem>.pkg" and bcastEntryPointUrl
Then <stem> must map (ids.fromFolderName) to a catalogue artifact whose layout.appDir exists, and the entry point file must exist inside it
And failures → blocking finding naming the missing piece
And a package URL that cannot be mapped to an application → note "could not resolve" (never a silent pass)
And adapter unavailable → skipped
```

## AC-5: V-XML-012 placeholders declared
```gherkin
Given attribute values and text in the document
When it contains example domains (example.org/.com/.net, *.example, *.test, *.invalid) or `urn:` values
Then the header's Assumptions section must mention each example domain, and must mention URNs/identifiers when urn: values exist
And each undeclared placeholder kind → note finding
And no placeholders → pass
```

```gherkin

Then no xml check reports "not implemented yet"
And the real AtlantisPB run is explainable (recorded in SUMMARY, not committed)
```
