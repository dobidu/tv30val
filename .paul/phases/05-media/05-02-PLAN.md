<objective>
## Goal
Implement V-MED-004: for each HSTREAM asset, parse its DASH (MPD) or HLS (m3u8) manifest and check it against the requirement stated in the catalogue description of that HSTREAM, read at runtime from `--root`.

## Purpose
HSTREAMs are the media the cases actually depend on (languages, subtitles, accessibility tracks, adaptive representations, deliberately broken manifests). A stream that doesn't carry what its case needs makes the case untestable — this is the content check check-structure.js cannot do.

## Output
- `lib/streams.js` (MPD + HLS manifest summarisers), reader gains element depth
- `lib/normative/stream-requirements.js` (generic phrase → predicate rules; no catalogue text committed)
- V-MED-004 in `lib/families/media.js`; fixtures; tests; README
</objective>

## Facts (private catalogue read at plan time; phrases only, not committed as data)
Requirement phrasings in HSTREAM descriptions (generic patterns):
- "own/distinct audio and visual reference", "audiovisual content", "media replacing" → has audio AND video
- "at least two audio languages" → ≥2 distinct audio languages
- "subtitles in at least two languages" → ≥2 distinct subtitle languages
- "sign-language stream" → a sign-language track
- "audio-description track" → an audio-description track
- "DASH content with multiple representations" → DASH, ≥2 Representations
- "HLS content" → HLS manifest
- "invalid manifest / unavailable" → manifest expected NOT to parse
- Not machine-checkable: dialogue enhancement, preference-dependent tracks, ratings, empty descriptions, external URLs
DASH signalling: AdaptationSet@contentType|@mimeType, @lang, Representation, Role/Accessibility (@schemeIdUri, @value: "sign", "description", or urn:tva:metadata:cs:AudioPurposeCS:2007 value 1). HLS: #EXT-X-MEDIA TYPE=AUDIO|SUBTITLES LANGUAGE= CHARACTERISTICS= (public.accessibility.describes-video), #EXT-X-STREAM-INF (RESOLUTION/CODECS → video).
</context>

<acceptance_criteria>

## AC-1: Manifest summaries
```gherkin
Given an MPD or m3u8 text
Then summarise() returns { kind: dash|hls, valid, error, audioLangs:Set, subtitleLangs:Set, hasAudio, hasVideo, representations, accessibility:Set(sign|description) }
And an MPD that is not well-formed or has no <MPD> root → valid:false with the reason; an m3u8 without #EXTM3U → valid:false
And an HLS media playlist (segments, no variants) is valid with representations = 1
```

## AC-2: Requirement rules
```gherkin
Given a catalogue description
Then stream-requirements.js maps it to zero or more predicates by generic phrase patterns (AC context list)
And a description matching no rule → "not machine-checkable"
And every rule carries its own source text "(to confirm)" pointing at NBR 25608 Annex B.4.3 where relevant
```

## AC-3: V-MED-004 per HSTREAM
```gherkin
Given an HSTREAM media item (directory with a manifest, or a single .mpd/.m3u8 file)
When its catalogue description maps to predicates
Then each failed predicate → blocking finding (requirement, what the manifest shows)
And all predicates hold → pass
And "invalid manifest" requirement: a valid manifest → blocking "expected an invalid manifest"; invalid or absent → pass
And no manifest found (and not the invalid case) → blocking "no DASH/HLS manifest"
And not machine-checkable → skipped with the description text
And HSTREAM not in catalogue → skipped (V-MED-001 already reports it)
And non-HSTREAM media → no V-MED-004 result
And no HSTREAM items at all → one skipped "no HSTREAM assets"
```

## AC-4: Directory manifests
```gherkin
Given a stream directory
Then the manifest is the top-level *.mpd, else the HLS master (top-level *.m3u8 containing #EXT-X-STREAM-INF), else the only top-level *.m3u8
And several candidate MPDs → the first by name, evidence lists the others
```
