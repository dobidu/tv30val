## AC-1: V-APP-001 folder ↔ ID
```gherkin
Given formal app folders
Then fromFolderName(folder) is a catalogue artifact of type F_3GHApp/F_3GNApp (not _SCRIPT/_AUX) → else blocking
And APPLICATION_ID in js/main.js (or main.lua), when present, equals that ID → else blocking
And filler folders: APPLICATION_ID, when present, must be "N/A" → else blocking
```

## AC-2: V-APP-002 entry point
```gherkin
Given a formal app
Then HTML5 (F_3GHApp) has index.html, NCL (F_3GNApp) has main.ncl → else blocking
And every BALD whose bcastEntryPackageUrl stem maps to this app announces a bcastEntryPointUrl that exists in the folder → else blocking (evidence: BALD path + line)
```

## AC-3: V-APP-003 package hygiene
```gherkin
Given app files (html, js, css, lua, ncl)
Then references to tools/, docs/, tools/dev-harness, node_modules or test files (*.test.js, *.spec.js) → should-fix with file:line
And files named *.test.js / *.spec.js or a test/ folder inside the app → should-fix
```

## AC-4: V-APP-004 README cases
```gherkin
Given README "## Test cases" table
Then each listed case exists in the catalogue and the app's artifact lists it → else blocking
And catalogue cases of the app missing from the README → note
And no README or no table → skipped (README form is readme.js's job)
```

## AC-5: V-APP-005 README input artifacts
```gherkin
Given README "## Input artifacts per test case" rows
Then per case: {PCAP + XML IDs in the row} equals {catalogue case artifacts of type F_PCAP or XML types} → each missing/extra ID blocking, naming the case
And a catalogued case of the app with no row → blocking
And "-", "N/A", empty → no IDs
```
